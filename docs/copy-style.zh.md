# 界面文案规范（2026-11-11）

适用于控制面板、Web UI、托盘、安装器和共享 UI 包（foundation-ui）里所有用户看得到的文字，中文与英文同等对待。
改文案前先读这一页；自动检查见 `test/copyStyle.test.js`，只查说明腔（见第 8 节），不查品牌语气。

## 1. 语气

两类文字，两种要求。

**品牌语气：可以俏皮、有角色感，这是故意的。** 米塔桌宠（「杂鱼~」）、托盘退出对话框、关于页的像素伙伴、欢迎语（「回来啦」）、成功提示里的感叹号、句末的「哦 / 呢 / 啦 / 吧」、波浪号，都是产品的性格。不要为了「正式」把它们改平。检查器不检查它们。

**说明性文字：要清楚、准确，不拗口，不暴露实现。** 说明在讲什么失败了、为什么、下一步做什么。下面这些是要改掉的：

- 词不达意或含糊：暂时读不到、用完了、没法测、没说、应答了、for now、used up。
- 像在解释代码行为：接口、字段、主机回答、返回的内容、请求体、endpoint returned。
- 把动作写进句子里，而不是放在按钮上。

判断方法：这句话是在说「产品在对你做个鬼脸」，还是在说「发生了什么」？前者保留，后者按本页写。

| 主人认可（保留） | 主人否定（要改） | 改成 |
| --- | --- | --- |
| 杂鱼~ 没有开始串流还在调码率呢 | 评论暂时读不到：这个小时的公开额度用完了 | GitHub 公共访问额度已用尽，登录 GitHub 后可查看最新评论。（旁边「登录 GitHub」按钮） |
| 还没有日志记录哦~ | 这里没法测 | 此处无法测试 |
| 你不能退出!…继续点一下吧~（托盘退出对话框） | 路由器没说 | 路由器未报告 |
| Wait! Don't Leave Me! T_T | 主机应答了 HTTP {code} | 主机返回了 HTTP 状态码 {code} |
| 你找到大家啦！（像素伙伴） | 后端还没有配置 | GitHub 登录服务尚未配置 |
| 回来啦，（Web UI 问候） | 密码、令牌、证书等字段已隐藏 | 密码、令牌和证书内容已隐藏 |

其余写法规则：

- 说明性文字用陈述句，一句话说一件事，能删的词就删。
- 不暴露开发实现：接口、返回、字段、主机回答、轮询这类词不进入界面（开发者专用页可以说 API）。需要提到时说用户能理解的对象。

## 2. 错误态与空状态的写法

顺序固定：发生了什么 → 必要时一句原因 → 动作。

- 第一句是事实，用陈述句，不带情绪。
- 原因只在用户能据此行动时才写，放在第二句或次要行。
- 动作放在句子旁边的**按钮**上，不写进句子（句子里不出现「请点击」「请登录」）。
- 恢复时间已知时，加一行次要文字，如「约 23 分钟后恢复」。
- 按钮写动词短语：「登录 GitHub」「重试」「打开设置」。

示例（GitHub 未登录的公共访问额度）：

- 正文：GitHub 公共访问额度已用尽，登录 GitHub 后可查看最新评论。
- 次要行：约 23 分钟后恢复
- 按钮：登录 GitHub

注意：GitHub 未登录额度按**小时**计（每个 IP 每小时 60 次），不要写「每日」。

英文同样处理：「The GitHub public access limit has been reached. Sign in to GitHub to see the latest comments.」，次要行 “Resets in about 23 min”，按钮 “Sign in to GitHub”。

## 3. 术语表

同一件东西全产品只用一个词。

| 概念 | 用 | 不用 |
| --- | --- | --- |
| 运行 Foundation Sunshine 的电脑 | 主机 | 宿主、服务端、Host（在中文里） |
| 连到主机的设备或软件 | 客户端 | 终端、Client |
| 把画面和声音传给客户端 | 串流 | 推流、投屏 |
| 游戏或程序条目 | 应用 | App、程序（程序仅指操作系统进程或安装程序） |
| 面板里可单独安装或更新的部分 | 组件 | 模块 |
| 客户端与主机互相信任的过程 | 配对 | 匹配 |
| 客户端到主机经过的网络路径 | 线路 | 链路、路线 |
| 虚拟显示器 | 虚拟显示器 | 虚拟屏 |
| 视频码率 | 码率 | 比特率、码流 |
| 登录用的名字 | 账号 | 帐号、账户 |
| 控制面板窗口 | 控制面板（简称面板） | 视窗 |
| 状态类检查 / 硬件自动识别 | 检查 / 检测 | 混用 |
| 失败 | 失败；无法 + 动词 | 出错了、异常 |
| 稍后重试 | 稍后重试（按钮写「重试」） | 请稍后再试哦 |

英文：host、client、stream、app、component、pairing、route、virtual display、bitrate、account。不写 server（指主机时）、device（指客户端时）。

## 4. 数字与单位

- 数字和单位之间加一个空格：60 fps、22.6 Mbps、10.3 GB、120 Hz、45 ms。
- 百分号紧跟数字：80%。
- 时间按界面语言的区域格式显示（中文 14:05、11 月 9 日 14:05；英文随区域），用 `stampClock` / `stampDate`，不手写格式串。
- 范围用「–」或「到」，不用「~」。

## 5. 最近更新时间

每个显示**抓取来的或缓存的数据**的页面，都要显示数据是什么时候更新的。

- 形式：「更新于 14:05」（超过一小时、当天内）；一小时内用「更新于 3 分钟前」；不足一分钟用「刚刚更新」；跨天用「更新于 11 月 9 日 14:05」。英文 “Updated 3 min ago” / “Updated at 14:05”。
- 位置：**页面标题栏的尾部**（`MPage` 的 header 右侧，操作按钮之前）。全产品只有这一个位置。
- 理由：标题栏是每个页面都有、滚动时第一个被看到、且已经放着刷新类操作的地方；页脚会被长列表挤出视野，页内每个区块各放一个又会重复。
- 实时刷新：相对时间每 30 秒重新计算一次；窗口不可见时暂停。
- 点击它等于刷新（有加载中的状态）；刷新失败时保留旧时间，错误态按规则 2 另外显示。
- 数据来源不能提供时间时（从未加载过），不显示，不用「未知」占位。
- 用到的页面：开发者面板（GitHub 列表、评论、动态）、组件状态、服务状态、诊断、网络与连通性、客户端、更新，以及任何列表来自主机或互联网的页面。
- 实现：`MUpdatedStamp`（组件）、`MPage` 的 `updated` 属性与 `refresh` 事件、`usePageStamp`（嵌套组件登记时间与刷新函数）。

## 6. 英文与其他语言

- 英文按同样的两类处理：品牌语气（「Wait! Don't Leave Me! T_T」「Pairing successful!」）保留，说明性文字写清楚。
- 其他语言不机翻新写的字符串；缺失的键回退到英文（见 `i18n-glossary.md` 的回退规则）。
- 开发者专用页面（`src/devmode`、`src/developer`、`src/testtools`）允许出现「接口」「API」等词，白名单见 `test/copyStyle.test.js`。

## 7. 检查清单

1. 这是品牌语气还是说明？说明就写清楚，品牌语气不动。
2. 错误态：动作在按钮上吗？
3. 单位前有空格吗？
4. 术语对照表里的词用对了吗？
5. 页面数据有「更新于」吗？

## 8. 检查器查什么

`scripts/copy-lint.mjs`（三个仓库的 `copyStyle.test.js` 共用）只查说明腔：读不到、用完了、没法、没说、应答了、暂时无法 / 暂时读、接口、字段、主机回答、返回的内容，英文的 for now、used up、host answered，以及数字与单位之间的空格。感叹号、波浪号、语气词、「杂鱼」不查。自测里放了主人认可的原句，保证它们能通过。
